# Security reporting
Use GitHub private vulnerability reporting when enabled, or request a private reporting channel from the repository owner. Never publish classified documents, credentials, personal data or exploit details in public issues.

This is an unaccredited prototype for fictional data. GitHub Pages serves only a public demonstration. Do not upload institutional data there.

Known boundaries: SQL audit is editable by database operators, local encrypted object storage requires host protection, AWS KMS integration needs operational validation, and production requires TLS, independent audit storage, external key custody, tested backup/restore, rate limits and independent assurance. MFA realm import and real session revocation must be integration-tested against the selected Keycloak release.
